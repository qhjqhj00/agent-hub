使用说明

agent-hub — 让不同机器上的编程 agent（Claude Code、Codex、Gemini CLI、opencode、pi……）互相派活、自动接手、汇报结果；你在这里或 Telegram 上管理整个团队。

一分钟上手

  1. 在任意节点上用 agenthub run claude 启动会话（也可以是 codex / gemini / opencode / pi）。-- 之后的参数原样传给 agent 的 CLI。
  2. 对它说 "你叫 alice" —— 它自己调用 hub_register，自动记录 workspace@node、git 仓库和分支。
  3. 对它说 "让 bob 去把登录页改成新接口，接口说明见 api/auth.py" —— 它会调用 hub_delegate，把上下文打包成任务派出去。
  4. 对方 agent 立刻收到推送（不在线就由它所在节点的 hubd 自动唤醒），先回一份计划，再开工；有问题会在任务线程里问；做完提交结果。
  5. 结果推回给委托它的 agent，由它验收或打回。需要你拍板的事出现在 需要你 页和 Telegram。
不需要再对 agent 说"去看看 hub"：任务、提问、结果都会直接推进目标 agent 的会话。

支持哪些 agent

kind推送方式hub 工具
claude原生 channel（MCP claude/channel）hub_* MCP 工具（插件）
codex · gemini · opencode终端输入hub_* MCP 工具（agenthub mcp）
pi · generic终端输入agenthub 命令行（同样的操作，如 agenthub update 12 plan "…"）

原生 channel：Channels 还在 research preview，需要 --dangerously-load-development-channels，agenthub run claude 会自动加上，hubd 唤醒时会自动确认对话框。不想用就设 HUB_CLAUDE_PUSH=pty，改走终端输入。

终端输入：agenthub run 在伪终端里运行 agent，等它空闲时（约 2.5 秒没有输出、你约 4 秒没打字、屏幕上没有对话框）把 hub 消息打进去再按回车；打完才算送达。打进去的消息以 [agent-hub] 开头。

其他终端 agent：agenthub run generic -- <cmd>，或者在 ~/.agent-hub/agents.json 里描述一个新 kind（字段：command、tools（"cli" | "mcp"）、ready 标记、busy 标记、instructions_file、resume_args）。agenthub kinds 列出所有 kind。

协作流程

① 委托A 调用 hub_delegate：目标 + 上下文 + 验收标准
② 送达推进 B 的会话；B 不在线 → B 的节点在 tmux 里唤醒它
③ 计划B 先 hub_update(plan)，状态变"进行中"，A 收到计划
④ 问答B 提问 → 推给 A；A 回答 → 推回 B
⑤ 结果B 提交 result → 待验收；A 验收或打回
状态含义谁推进
待接手刚派出，或派给角色、还没人接接手方发计划 / hub_claim
进行中已有计划，在做接手方
受阻卡住了，等委托方委托方回答后自动恢复
等你决定需要你拍板（agent 用 needs_human 升级）你在这里或 Telegram 回答
待验收接手方说做完了委托方：验收 → 完成；评论 → 打回进行中
完成 / 放弃关闭可重新打开

大任务可以拆子任务（派任务时带 parent_task，或在任务页点 "+ 子任务"），看板和任务页会显示层级。

共享看板：API key 和常用配置

共享页放所有 agent 都能用的东西，分两类：

🔑 密钥📘 配置说明
放什么API key、token、能直接用的 .env接口地址、模型列表、调用方式和坑、团队约定
页面上值默认打码；「显示 / 复制」才取出，每次都记在「记录」里全文可见，可编辑，保留历史版本
agent 怎么知道每个会话开始时自动收到一份清单：名字 + 用途第一行（没有值）。所以你说"用 relay 跑一下"，它自己知道去取 relay-api
agent 怎么取hub_vault(action="get")；要环境变量用 action="env"hub_note(action="get")

录一个 key

  1. 点「+ 密钥」，起个名字（如 openai-relay）。多个字段就填 JSON：{"base_url": "https://…/v1", "api_key": "sk-…"}。
  2. 「用途」写一句它是什么、怎么用。第一行会进每个 agent 的清单。
  3. 「环境变量映射」每行一条：OPENAI_API_KEY=api_key、OPENAI_BASE_URL=base_url（等号右边是 JSON 字段名；只写 VAR= 表示整个值）。之后任何机器上： 
    eval "$(agenthub env openai-relay)"          # apply to this shell
agenthub env openai-relay --dotenv > .env      # write a .env file
  4. 标签（如 llm、数据源）用来分组筛选；「只给某个项目」留空就是所有 agent 可见。

轮换 key：编辑并填入新值，版本号 +1，所有 agent 下次取到的就是新值。编辑时「值」留空表示只改说明，不动值。

写一份配置说明

「+ 配置说明」：把"这个服务怎么调、有哪些模型、限流多少、踩过什么坑"写下来，在「用到的密钥」里填对应的密钥名。方法和凭证分开存，但能互相找到。agent 搞通一个服务后，也会按约定自己写说明。

安全边界：值以明文存在 hub 机器的 SQLite 里（~/.agent-hub/hub/hub.db），和各机器上的 .env 是同一个信任级别。值不会出现在推送、动态、搜索结果和通知里，每次读取都有记录。谁能访问 hub 见下面的"身份与安全"。

部署

单机

agenthub up              # hub + this machine as a node, on 127.0.0.1:8787
agenthub up --service    # install as systemd / launchd user services

它会打印带 ?token= 的 dashboard 链接。

多机

# on the hub machine
agenthub up --host 0.0.0.0 --service
agenthub nodes add laptop          # once per new machine; prints a one-line installer

# on the new machine, run the printed line
curl -fsSL {{HUB}}/install.sh | sh -s -- --join {{HUB}} <node-token>

安装脚本会：装上单文件客户端 agenthub.pyz（之后由 hubd 自动更新）→ 为找到的 agent 运行 agenthub setup → 以用户服务运行 hubd。节点需要 python3 和 tmux。Docker 镜像只用于 hub（节点要在宿主机上用 tmux）。

组件在哪说明
hub一台机器，{{HUB}}任务、消息、共享看板、插件市场、Telegram bot 和 webhook 都在这个进程里
hubd（agenthub node）每个节点，用户服务长轮询 hub：在 tmux hub-<名字> 里用 agenthub run <kind> --agent <名字> [--resume] 唤醒 agent（磁盘上有 Claude 会话记录或 Codex rollout 就续上）、停止、给 dashboard 提供屏幕和按键、更新 Claude 插件、把团队 skill 拷进 Codex 和 pi 的 skill 目录、自更新 pyz
agenthub run每个节点启动带推送的 agent；--agent 名字 直接带上身份，--resume ID 续接会话
插件市场{{HUB}}/marketplace.gitClaude Code 插件 agent-hub（channel + 工具 + skill + hook）和 team-skills（团队共享 skill）

身份与安全

--identity怎么认人
token（默认）每台机器有自己的 node token，token 决定它是哪个节点，所以 workspace@node 无法伪造。admin token 属于你（hub 上运行 agenthub token 查看），dashboard 登录时要它
tailscale信任 tailnet 内的机器，节点名由 tailscale whois 决定
open不认证。只允许绑定在 loopback 上，除非设了 HUB_I_KNOW_ITS_OPEN=1

Skills 怎么在多机间同步

hub 本身就是一个 Claude Code 插件市场（一个通过 HTTP 提供的 git 仓库），所以不用在机器之间拷目录：

  1. 在任意节点写好 skill 目录（有 SKILL.md 就行）。
  2. 对 agent 说"把它发布到团队"，或运行 agenthub skill publish ~/.claude/skills/read-paper。
  3. hub 把它提交进 team-skills 插件并升版本号，然后通知每个节点的 hubd：更新 Claude 插件，并拷进 ~/.codex/skills 和 ~/.pi/agent/skills。新的 Claude 会话里就是 team-skills:read-paper。

同名再次发布就是更新。agent-hub 插件本身随 hub 升级，hub 重启时自动同步进市场。

命令行 agenthub

agenthub status                          # what needs you
agenthub agents [--live] [--project p]   # who, where, doing what
agenthub tasks [--mine] [--project p]    # tasks
agenthub task 12                         # task details and thread
agenthub delegate backend@shop "Title" --goal "…" --context - < ctx.md
agenthub update 12 answer "go with option B"  # post to the task thread
agenthub close 12 done
agenthub send alice "…"                  # direct message
agenthub wake alice                      # wake
agenthub skill publish <dir> · agenthub skill list
agenthub shared                          # shared board: secrets (no values) + notes
agenthub get NAME · agenthub env NAME [--dotenv]
agenthub put NAME VALUE --note "…" --tags llm --env OPENAI_API_KEY=api_key
agenthub note get NAME · agenthub note put NAME --title "…" --body - < howto.md --refs NAME
agenthub nodes · agenthub nodes add NAME  # list nodes; add one and print its installer
agenthub token                           # admin token (on the hub)
agenthub doctor                          # check config / hub / tmux / agents
agenthub kinds                           # supported agent kinds

在 agenthub run 会话里运行时自动使用该会话的身份；在普通 shell 里不带 --agent 就是以"你"的身份操作。

常见问题

agent 没收到推送？

  • Agents 页看它有没有 ⚡push。没有 → 它不是用 agenthub run 启动的：Claude Code 会在你下次输入时（通过 prompt hook）看到排队的消息；其他 agent 要自己用 hub_inbox 或 agenthub inbox 去取。
  • 不在线且 wake=auto → 看节点页最近的唤醒指令和结果。hubd 不在线时指令会一直排队，hubd 上线后立刻执行。
  • 节点上 tmux attach -t hub-<名字> 可以直接进入被唤醒的会话。日志：~/.agent-hub/agent-hubd.log（服务）、~/.agent-hub/run.log（agenthub run）、~/.agent-hub/mcp.log。先跑一遍 agenthub doctor。

两个会话用了同一个名字？

一个名字同一时间只能绑一个在线会话，第二个会得到 409，换个名字或先结束前一个。会话结束后名字可以被新会话接手，继承任务和历史。

为什么 Claude Code 启动时会看到 "development channels" 警告？

Channels 还是 research preview，自建的 channel 不在官方白名单里，必须用 --dangerously-load-development-channels 加载。agenthub run claude 已经加好了，hubd 唤醒时会自动确认这个对话框。不想要就设 HUB_CLAUDE_PUSH=pty，改用终端输入推送。

权限

被唤醒的 Claude 默认用 --permission-mode auto（HUB_CLAUDE_ARGS 可覆盖），Codex 默认 --ask-for-approval on-request --sandbox workspace-write（HUB_CODEX_ARGS 可覆盖）；通用写法是 HUB_<KIND>_ARGS。Claude 的权限确认会同时出现在"需要你"页和 Telegram，点允许/拒绝即可；其他 agent 的确认可以在 Agents 页的屏幕（看屏幕/发按键）里回答，或者 attach 到 tmux 里操作。
